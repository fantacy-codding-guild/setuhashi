# SetuHashi website — Next.js implementation (design baseline v4.10.2)

The approved bilingual (English / 日本語) site from the developer handoff, rebuilt on **Next.js 16 (App Router, React 19, TypeScript)**.
Design, copy, routes, films and behaviour are the frozen v4.10.2 baseline — this is a framework port, not a redesign.

```
npm install
npm run dev        # http://localhost:3000  (use localhost, not 127.0.0.1, unless listed in allowedDevOrigins)
npm run build      # static export -> out/   (no Node server needed; upload out/ to Hostinger)
npm run typecheck
```
Node 20+ (built and tested on Node 22).

## What you get
* **323 static pages**: `/` (language selection), `/en/` + `/ja/` (welcome), 158 + 158 section/offering/story/people pages, privacy, and a bilingual `404.html`.
* **Clean URLs** with a trailing slash: `/en/what-we-offer/`. The original `*.html` addresses keep working through `public/.htaccess` (301 → clean URL, query string preserved).
* **Same visuals**: the original `fonts.css` / `v4.css` and all assets (logos, portraits, bundled font subsets, both films, posters, VTT captions) are used unchanged from `public/assets` / `app/styles`.
* **Same behaviour**: the five original scripts are ported to typed modules in `lib/behaviors/` (header hide-on-scroll + phone menu, offer cards + history state, experience filters, contact topic/validation, intro video dialog). They clean up after themselves, so they work with client-side navigation and React Strict Mode.

## How it is organised
| Path | Role |
|---|---|
| `app/(entry)/` | Root language-selection page (its own root layout, `<html lang="en">`) |
| `app/(site)/[lang]/` | `en` / `ja` root layout (`<html lang>`, `js` class, body class) · `page.tsx` = welcome · `[slug]/page.tsx` = every other page |
| `app/global-not-found.tsx` | 404 for static hosting |
| `components/Header.tsx` `Footer.tsx` | Shell rendered in React from `lib/site.ts` (labels, nav, review-banner text) |
| `components/SitePage.tsx` | Page frame: skip link, review banner, header, `<main>`, footer, behaviours |
| `content/{en,ja}/<slug>.json` | Page title, description, `<main>` class, body HTML (links already rewritten to Next routes), scripts, language-switch target |
| `lib/behaviors/*` | Ported browser behaviour |
| `scripts/extract_content.py` | Regenerates `content/` from the handoff's `01_WEBSITE_REVIEW_REFERENCE/site` |
| `scripts/verify_fidelity.py` | Compares every exported page's DOM with the original (see below) |
| `tests/e2e.py` | Playwright checks of the behaviours against a served `out/` |

### Editing content
The 160 + 160 page bodies are stored as HTML fragments generated by the original Python build (`02_SOURCE/build`), which remains the authoring source for copy and layout. Two options:
1. change copy in the Python modules, run its build, then `npm run extract -- <path-to>/site` (or `python3 scripts/extract_content.py <path>`); or
2. edit `content/<lang>/<slug>.json` directly (keep EN and JA in step).
Small, one-off edits are fine in the JSON; converting the portfolio/experience data into React components was deliberately **not** done (it would re-implement 320 generated pages and risk drift from the approved design).

## Verification performed
* `npx next build` — 323 pages, TypeScript clean.
* `scripts/verify_fidelity.py` — **321/321 pages** (160 EN + 160 JA + root) are DOM-identical to the originals after the intentional rewrites (`x.html` → `/lang/x/`, `../assets` → `/assets`, base64 caption tracks → the shipped `.vtt` files, which were checked byte-identical, script tags ignored).
* `tests/e2e.py` (headless Chromium on the static export): page loads with no console errors or failed requests · `lang`/`js` class · phone menu open/Escape/focus · local menus closed on narrow · intro dialog open/Close/Escape/scroll lock/focus · offering cards, `#o-…` address, history state, reload restore · compatibility pages replace themselves (query + anchor kept) · experience filters, `#f=` address and restore · language switch keeps query/hash · contact topic, Remove topic, validation, inactive example form · header navigation is a client-side navigation and behaviours re-initialise · browser Back.
* Dev mode (React Strict Mode double effects): intro dialog and filters verified, no console warnings.

**Not verified** (needs real devices / hosting): Safari/iOS and Firefox, screen-reader pass, the `.htaccess` redirects on an actual Apache/Hostinger server, Back/Forward regression matrix from the handoff's acceptance checklist. Historical author QA does not substitute for testing a staging URL.

## Intentionally unchanged from the handoff (still open items)
* **Review build markers**: the "internal review build" banner, footer note and `noindex, nofollow` are still on. Do not publish this build as is.
* **Enquiry form** is still the inactive example (no action, nothing sent). An approved enquiry path and the final privacy copy are separate decisions.
* **Browser-Back discrepancy in the intro player** is reproduced exactly as in the frozen source (opening the player adds no history entry) and documented in `lib/behaviors/intro.ts`. It needs a Sponsor decision or a carefully tested history implementation.
* In-content links are ordinary anchors (full page loads, exactly like the original, so the history-state/Back logic is unchanged). Header, footer and welcome-page navigation use `next/link` client-side navigation.
* The films are served as supplied (not re-encoded).
